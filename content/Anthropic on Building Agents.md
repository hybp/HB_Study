1. Agent vs Workflow / Tool / Function Use
	Workflow / Tools / Function Use:
		- Fixed number of processes
		- input / output pretty much fixed expected
	Agent:
		- Don't know when you will get an answer
		- How many iterations
		- Let LLM to do until you find the answer

2. Still many problems that people 간과
	- Function, Tool이든 다 설명이 필요하다. Prompt Engineering

3. Underhyped / Overhyped
	- 작은 시간이 걸리는 automation이더라도 자동화가 가능한 것에 대한 주목
	- Coding and Search
	- Not much about consumer side benefits
	- 생산성, efficiency, business operation side 효과가 더 클것
		- Consumer side에 agent를 제공하려면 엄청난 정확도가 필요하다는 risk
		- Agent를 사용하더라도 사용자 결정, input이 필요한 부분이 많다
		- 그걸 다 하려면 차라리 그냥 사람이 하는게 더 나은 경우도 많아서

4. About Coding Agents
	- Verifiable (Test 가 존재) 하다는 점이 극 강점
	- 여러차례 iterate 하면서 agent가 어떤 테스트를 통과 못했는지 뭐가 문제인지에 대한 feedback이 있다는 점이 agentic workflow allow
	- 정답으로 converge 할 수 있다
	- 또, valuable task는 높지만 cost of error가 상대적으로 낮은 작업에 agent를 두면 좋을 것
		- e.g. Iterative Searching : Extensive searching : Agentic Searching
			- Trade off precision for recall
			- Get more documentation, more information than needed
