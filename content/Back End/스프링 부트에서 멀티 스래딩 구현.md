
###  ※! 스프링 부트에서는 서블릿 컨테이너인 Tomcat이 다중 요청 처리
참고: [[웹서버와 웹앱서버 (WS, WAS) 그리고 리버스 프록시]]


### 요약 워크플로우
1. Tomcat에서 Thread Pool 생성
2. 요청이 들어오면 스래드 Pool에서 하나식 Thread 할당
3. 작업이 끝나면 스레드는 풀로 반환

참고: [[스레드풀이란]]

### 톰캣 설정
```python
# application.yml (적어놓은 값은 default)
server:
  tomcat:
    threads:
      max: 200 # 생성할 수 있는 thread의 총 개수
      min-spare: 10 # 항상 활성화 되어있는(idle) thread의 개수
    max-connections: 8192 # 수립가능한 connection의 총 개수
    accept-count: 100 # 작업큐의 사이즈
    connection-timeout: 20000 # timeout 판단 기준 시간, 20초
  port: 8080 # 서버를 띄울 포트번호
```


### 전체 워크플로우
1. 첫 작업이 들어오면, **core size**만큼의 스레드 생성
2. 유저 요청(Connection, Server socket에서 accept한 소캣 객체)이 들어올 때마다 작업 큐에 저장
3. 큐에서 꺼내기
	3-1. Idle인 스레드가 있다면 idle 스레드에 할당
    3-2. Idle 스레드가 없다면, 작업 큐에서 대기
    3-3. 상태가 지속되어 작업 큐가 꽉 찬다면, 스레드를 새로 생성
    3-4. 스레드 최대 사이즈 에 도달하고 작업큐도 꽉 차게 되면, 
        추가 요청에 대해 connection-refused 오류 반환
4. 태스크가 완료되면 스레드는 다시 Tread Pool에 Idle로
    4-1. 작업큐가 비어있고 core size이상의 스레드가 생성되어있다면 스레드를 destroy

참고로 스레드가 너무 많아지면 CPU Context Switching이 일어나 overhead 발생
