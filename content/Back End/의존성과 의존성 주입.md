e.g. Strong Dependency

```java
public class Consumer {

	void eat() {
	
		Chicken chicken = new Chicken();
		chicken.eat();
		
	}
	
}

}

class Chicken {

	public void eat() {
		
		System.out.println("치킨을 먹는다.");
	
	}

}
```

강한 의존성 때문에 치킨이 아닌 다른걸 먹고 싶을 때 많은 코드를 수정해야 한다.

제어의 흐름 또한 Consumer -> Food

e.g. Weak Dependency

```java
public class Consumer {

	void eat(Food food) {
		food.eat();
	}
}

interface Food {
	void eat();
}

class Chicken implements Food {

	@Override
	public void eat() {
		System.out.println("치킨을 먹는다.")
	}

}

class Pizza implements Food {

	@Override
	public void eat() {
		System.out.println("피자를 먹는다.")
	}

}
```

결합이 약하기 때문에 Consumer 코드를 수정할 필요 없다

제어의 흐름 바뀜 (이 말의 뜻은 아래에서 설명)

## Dependency Injection

느슨한 연결 상태에서 필요한 객체들만 주입 시켜주는것


```java
public class Consumer {

	# Dependency
	Food food;

	# Injection with Constructor
	public Consumer(Food food) {
		this.food = food;
	}

}

interface Food {

	void eat();

}

class Chicken implements Food {

	@Override
	public void eat() {
		System.out.println("치킨을 먹는다.");
	}

}

```

Consumer가 무엇을 먹게 되는지는 Consumer의 코드가 아니라 Food의 코드를 따르기 때문에

제어의 흐름이 Food -> Consumer로 바뀌었다.

느슨한 결합 -> 서로 필요한 부분만 의존하고 있음 -> 코드 수정 양 down
